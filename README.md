# did-vc-iot-iam

## Project Summary

This repository implements a DID and Verifiable Credential based IAM pipeline for IoT using Hyperledger Fabric as a permissioned metadata ledger. It covers device onboarding, DID registration and resolution, Identity VC issuance, Capability VC issuance, proof of possession, authorization decisions, accumulator based revocation, audit logging, a dashboard demo, performance benchmarking, and constrained device emulation.

## What This Repository Is For

This is a final year research prototype, not production IAM software. It is used to evaluate feasibility, latency, resource use, ledger overhead, revocation behavior, and constrained device agent behavior for a permissioned DID/VC IoT IAM design.

## Architecture Overview

```text
Device agent -> Issuer service -> Verifier service -> Fabric adapter -> Hyperledger Fabric
Dashboard UI -> Dashboard API -> Issuer, Verifier, Fabric adapter
```

The device agent holds device keys and credentials. The issuer registers DIDs and issues VCs. The verifier checks signatures, proof of possession, capability claims, expiry, and revocation state. The Fabric adapter connects services to Fabric chaincode. Fabric stores only compact metadata, not full credentials. The dashboard shows and controls the research demo.

## Fabric Samples Setup

Fabric Samples is an upstream dependency. It is large and should not be committed or vendored into this repository. This repo only documents how to install it. The recommended layout keeps it beside the project source but outside git tracking:

```text
did-vc-iot-iam/
  third_party/
    fabric-samples/
```

Recommended Git Bash install from the repository root:

```bash
mkdir -p third_party
cd third_party
curl -sSL https://bit.ly/2ysbOFE | bash -s -- 2.5.15 1.5.15
cd ..
```

The official Fabric install script creates or updates `fabric-samples` in the current working directory, so running it from `third_party` installs to `third_party/fabric-samples`.

PowerShell-friendly option:

```powershell
mkdir third_party
cd third_party
curl.exe -sSL https://bit.ly/2ysbOFE -o install-fabric.sh
bash install-fabric.sh 2.5.15 1.5.15
cd ..
```

If the PowerShell flow fails because `bash` is not available in that shell, use Git Bash for this step.

Optional helper scripts:

```bash
bash scripts/setup_fabric_samples.sh
```

```powershell
.\scripts\setup_fabric_samples.ps1
```

Advanced users can install Fabric Samples anywhere else and set:

```text
FABRIC_SAMPLES_PATH=C:/path/to/fabric-samples
FABRIC_SAMPLES_ORGS_HOST_PATH=C:/path/to/fabric-samples/test-network/organizations
```

## Environment Setup

Copy the project env example before running the dashboard or Fabric Compose stack:


```text
FABRIC_SAMPLES_PATH=C:/Users/<user>/Documents/CodingProjects/did-vc-iot-iam/third_party/fabric-samples
FABRIC_SAMPLES_ORGS_HOST_PATH=C:/Users/<user>/Documents/CodingProjects/did-vc-iot-iam/third_party/fabric-samples/test-network/organizations
```

```text
FABRIC_SAMPLES_ORGS_HOST_PATH=C:/Users/<user>/Documents/CodingProjects/fabric-samples/test-network/organizations
```

`FABRIC_SAMPLES_PATH` points to the Fabric Samples root. `FABRIC_SAMPLES_ORGS_HOST_PATH` points to `test-network/organizations`, which exists after the Fabric test network has been started.

## Fabric Network Setup

Start and deploy the Fabric test network from Git Bash:

```bash
cd fabric
bash ./network.sh down
bash ./network.sh up
bash ./network.sh deployCC-docker
bash ./network.sh ping
```

Use `deployCC-docker` so local Go is not required. The Fabric test network must be running before the Fabric Compose stack and dashboard stack.

## Full Dashboard Quick Start

1. Install Fabric Samples into `third_party/fabric-samples`.
2. Copy `.env.project.example` to `.env.project`.
3. Edit `.env.project` and set the Fabric Samples paths.
4. Start Fabric from Git Bash:

```bash
cd fabric
bash ./network.sh down
bash ./network.sh up
bash ./network.sh deployCC-docker
bash ./network.sh ping
```

5. Start the full stack from PowerShell:

```powershell
docker compose --env-file .env.project -f docker-compose.yml -f docker-compose.fabric.yml -f docker-compose.perf.yml -f docker-compose.dashboard.yml up -d --build
```

6. Open:

```text
http://localhost:5173
```

7. Run the demo flow:

```text
Reset Session
Add Device
Issue Identity VC
Issue Capability VC
Authorize Request
Revoke Capability VC
Verify revoked access is denied
Issue replacement Capability VC
Refresh accumulator proof
Verify restored access
```

## Reset Behavior

Dashboard Reset Session clears only dashboard SQLite state. It does not reset Fabric ledger data. It does not reset issuer runtime files unless a separate cleanup command does that. It does not reset verifier runtime files unless a separate cleanup command does that. Fabric reset is manual from Git Bash.

Fresh demo rule:

```text
Reset Session -> Add Device -> Issue Identity VC -> Issue Capability VC -> Authorize Request
```

## Revocation And Accumulator

`REVOCATION_MODE=status` uses status lookup. `REVOCATION_MODE=accumulator` requires accumulator proofs. `REVOCATION_MODE=hybrid` checks accumulator proof first and keeps status lookup as a safety baseline.

The accumulator is an EVOKE inspired Merkle accumulator prototype using deterministic SHA-256 Merkle roots. It is not the exact ECC accumulator from EVOKE. The issuer stores local accumulator records. Fabric stores compact accumulator state metadata only. Full VCs and witness lists are not stored on Fabric. Proof refresh lets active credentials update their witness after the accumulator root changes. Revoked credentials cannot refresh proof.

## Fabric Design

The target Fabric version is `2.5.15`. The target Fabric CA version is `1.5.15`. The project uses the official Fabric Samples test network. The test network uses Raft ordering. Chaincode is written in Go.

Fabric stores metadata only:

- DID metadata
- credential status metadata
- revocation status
- audit events
- accumulator root and state metadata

Fabric does not store:

- full VCs
- private keys
- witness lists
- sensor data

Default Docker Compose Fabric mode uses a long-running `fabric-adapter` service. The adapter sends peer chaincode query and invoke commands to Fabric and avoids starting a new Fabric tools container for every ledger operation. Peer CLI mode remains as a compatibility option where supported.

## Benchmarking

The dashboard can run the pipeline benchmark, Fabric operation benchmark, resource usage benchmark, constrained device profile benchmark, and combined benchmark suites from its Performance page.

Timing rule: measured lifecycle excludes setup, health checks, wallet reset, container startup, and artificial cache wait. Raw wall clock and excluded wait may be exposed for debugging.

Core commands:

```powershell
python scripts/benchmark_pipeline.py
python scripts/benchmark_fabric_ops.py
python scripts/run_all_tests.py --mode local
python scripts/run_all_tests.py --mode fabric
python scripts/run_all_tests.py --mode perf
```

Useful benchmark scripts:

| Script | Purpose |
| --- | --- |
| `scripts/benchmark_pipeline.py` | Runs the core DID, VC, authorization, revocation, proof refresh lifecycle. |
| `scripts/benchmark_fabric_ops.py` | Measures Fabric chaincode read/write operation costs. |
| `scripts/benchmark_constrained_profiles.py` | Runs gateway, constrained, low resource, and tiny IoT device-agent profiles. |
| `scripts/benchmark_revocation_connectivity.py` | Exercises stale proof, proof refresh, and network disruption behavior. |
| `scripts/run_fabric_tuning_matrix.py` | Runs Fabric tuning experiments. |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| Missing `FABRIC_SAMPLES_PATH` | Copy `.env.project.example` to `.env.project` and set the path. |
| Missing `FABRIC_SAMPLES_ORGS_HOST_PATH` | Start the Fabric network first and check that `test-network/organizations` exists. |
| Docker volume path issue on Windows | Use absolute paths with forward slashes. Avoid spaces in paths. |
| Fabric Samples not found | Install it into `third_party/fabric-samples` or set `FABRIC_SAMPLES_PATH` to an external location. |
| Capability VC proof refresh failed | Reset Session, Add Device, Issue Identity VC, then Issue Capability VC. |
| Dashboard shows stale data after Fabric reset | Reset the dashboard session. |
| Fabric adapter cannot reach peer | Check that the Fabric network is up, chaincode is deployed, and the organizations path is correct. |
| Ports already in use | Stop old containers or change ports. |
| Vite large chunk warning | Build can still pass unless npm exits non-zero. |

## Out Of Scope

- Aries or DIDComm interoperability
- selective disclosure or BBS+ on edge devices
- full TPM, PUF, or secure element to DID binding
- production wallet compatibility
- full credential storage on Fabric
